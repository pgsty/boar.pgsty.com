Boar `v0.2.0` is the frozen Fusion **acceptance baseline** at source
`38f0a546fb0b1d6e3c7bf37fb422d68e26fc0544`. It combines native Patroni
control, typed etcd and PostgreSQL providers, fleet aggregation, durable
approval/Job/Audit governance, Pigsty operations, and a unified bilingual Web
experience.

> [!NOTE]
> The Charter explicitly says this acceptance anchor is not proof that `dev`
> was promoted to `main` or that a public `v0.2.0` Git tag and release were
> created. This page preserves the historical acceptance record and permanent
> compatibility contract; it does not claim a confirmed public release.

## Highlights

- Native parity for all 19 Patroni CLI commands without Python at runtime.
- Typed success, rejection, conflict, unreachable, cancellation, and
  `UNKNOWN/MAYBE_SENT/UNCONFIRMED` results across SDK, API, Audit, and Web UI.
- Three-scope fleet discovery/watch and a controlled
  100-scope/500-member performance gate.
- Durable encrypted Plan artifacts, current authorization, terminal Job/Audit
  convergence, and startup no-replay recovery.
- Pigsty inventory import, desired/recorded/actual state, allowlisted planning,
  and isolated real control-plane lab evidence.
- Real Chromium journeys against PostgreSQL `18.4` and the four-node lab.

## Historical acceptance artifacts

The accepted artifact contract contains exactly:

```text
boar-v0.2.0-linux-amd64.tar.gz
boar-v0.2.0-linux-arm64.tar.gz
boar-v0.2.0.cdx.json
boar-v0.2.0-build-receipt.json
SHA256SUMS
SHA256SUMS.sig
RELEASE-PUBLIC-KEY.pem
```

Each archive contains the embedded frontend, `LICENSE`, `README.md`, and one
static Boar binary. Builds use canonical tar metadata, `SOURCE_DATE_EPOCH`,
`-trimpath`, `-buildvcs=false`, and an empty Go build ID. Two builds per
platform must be byte-identical.

Verify the trusted Ed25519 public-key fingerprint out of band, then run:

```bash
openssl pkeyutl -verify -pubin -inkey RELEASE-PUBLIC-KEY.pem \
  -rawin -in SHA256SUMS -sigfile SHA256SUMS.sig
sha256sum -c SHA256SUMS
jq -e '.bomFormat == "CycloneDX" and .specVersion == "1.6"' \
  boar-v0.2.0.cdx.json
```

The historical gates reject tampered archives, missing SBOMs, extra artifacts, and
modified signatures before running both architectures as numeric UID/GID
`65532` in scratch images against the pinned PostgreSQL service.

## Migration context

If operating this accepted snapshot, its metadata schema contains forward-only migrations `0001` through
`0010`. Back up the exact `boar` database, drain confirmed writes, record every
UNKNOWN, run `boar migrate`, and verify the migration ledger before restart.

Follow [Install, upgrade, and recovery](/docs/admin/upgrade-recovery/).

## Breaking changes

- The public Fusion API baseline is `v0.2.0` / `v1alpha1`; callers use typed
  target and result contracts instead of private legacy structures.
- Confirmed mutations require exact Plan/action/target identity and may return
  durable UNKNOWN instead of unsafe retry.
- Configuration sources and credential files enforce canonical path, owner,
  mode, no-symlink, size, and precedence rules.
- Encrypted PostgreSQL client private keys are rejected before decrypt/KDF.
- Release containers run as numeric UID/GID `65532`, not root.

## Compatibility

The reviewed matrix includes Go `1.26.6`, Node.js `26.4.0`, PostgreSQL `18.4`,
Patroni `4.0.7` plus the pinned `4.1.0` source lane, and etcd `3.5.33`, `3.6.14`,
and `3.7.1`. Consult the [compatibility matrix](/docs/reference/compatibility/)
for source pins and approved deviations.

## Known limitations

- Browser evidence covers Chromium, not Firefox or WebKit.
- Claude Code is external to the scratch release image; absence produces a
  bounded degraded Assistant health state.
- Rollback is backup/restore based; there are no down-migrations.
- Ambient libpq behavior outside the hardened provider subset is not promised.
- Local evidence cannot substitute for a required named remote-CI run.

## Evidence boundary

TLS/auth/source checks, Patroni control, fleet performance, Pigsty lab, browser
E2E, packaging, and remote CI remain independent evidence lanes. Passing one
never synthesizes another.
